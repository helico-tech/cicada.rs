# Decisions

The decisions of Cicada for Rust, one ADR per file (Nygard format: status, context, decision, consequences). An
accepted ADR is not rewritten: a later one supersedes it. A change that makes a decision adds its ADR's row here.

| ADR | Decision |

| [0003](0003-actor-definition-api.md) | Actor definitions: a ref struct implementing `ActorRef`, a tagged serde enum, and the `Actor` trait with one `handle`; no proc macro. Its unhandled policy is gone (0018). |

| [0010](0010-openspec-for-work-tracking.md) | Changes, designs and tasks live in `openspec/` (OpenSpec). |
| [0011](0011-library-only.md) | A library only: no console, no container handles. Partly superseded by 0056 and 0076. |
| [0012](0012-slimmer-api-and-wire-format.md) | A slimmer API and wire format: turn hooks that only observe (replaced by one observer in 0018), one way to configure and send, ISO-8601 durations only, twelve endpoints. |
| [0013](0013-type-and-key-addresses.md) | Actors are addressed by type name and key (`sync/acme`) instead of URIs. |
| [0014](0014-management-reads-and-type-removal.md) | Management reads over HTTP (outcomes, stats, caused-by) and removing a type's registration. |
| [0015](0015-operator-actions.md) | Operator actions: node table, cancelling a running turn, pausing and purging a mailbox, retrying a message, bulk actions; the store refuses creates of an unregistered type. |
| [0016](0016-releases-are-tags.md) | A release is a tag on `main` with one version for the workspace; a release passes all checks first and never moves. Its release workflow and failed-tag deletion are superseded by 0046. |
| [0017](0017-contracts-ignore-descriptions-and-stores-refuse-foreign-databases.md) | A contract hash leaves out the schemas' descriptions (the published contract keeps them); the SQLite store refuses a database that holds other tables. |
| [0018](0018-a-smaller-core-layers-and-watches.md) | A smaller core (every actor has state, one-name keys, one turn observer in place of three hooks, no public store trait), layers above it (`cicada-app`, `cicada-actors`), JSON Schema checks at the HTTP door, watches and control effects. |
| [0019](0019-child-actors.md) | Child actors: an actor may have a parent, the actor whose turn created it, and removing the parent removes what it owns. |
| [0020](0020-the-change-loop.md) | Superseded by 0030. |
| [0021](0021-a-key-is-one-name.md) | A key is one name: a ref is written as one string or a unit, a `:` is an ordinary character, contracts hold no key fields, and a database is upgraded in place. |
| [0022](0022-typed-errors-and-no-such-type.md) | Typed errors: a named error per module, a start error with a problem per cause (a contract conflict is its own case), a send to an unregistered type answers `404 no-such-type`, and a migration that violates a constraint is an invalid store. |
| [0023](0023-the-rules-of-a-watch.md) | The rules of a watch: notifications in the watcher's own family, a type target at a dot and `*` for every type (failures only), `Stopped` with its cause and `by`, a notification marked and named after its event, and G2 and G4 that name the notifications. |
| [0024](0024-control-effects.md) | Control effects: a turn pauses, resumes, purges and deletes another actor with the meaning of the operator's calls, an effect on an actor that is not there does nothing, a turn cannot delete itself or an ancestor, deletes come before creates (a restart), and G1, G2 and S7 that say so. |
| [0025](0025-the-claim-limit.md) | The claim limit: a message counts its lost claims (a claim that another claim replaced although its turn neither committed nor gave the lease back), a node fails a message with as many as its limit (5 by default) through a commit that tells its watchers, and G4 that names the limit. |
| [0026](0026-the-schema-check-at-the-http-door.md) | The schema check at the HTTP door (narrowed by 0029): a send and a create over HTTP are checked against the registered schema on every node and refused with `422` (not `400` as 0018 said), a hosting node still decodes, a repeated send is answered first, no format is asserted, a schema the validator cannot use is not enforced, and JSON that code sends is not checked. |
| [0027](0027-the-app-layer.md) | The app layer: `serve` takes `--types` too, a binary without types has neither `serve` nor `worker`, `App` has no authentication of its own and `serve` listens on `127.0.0.1:8080` unless told otherwise, the node stops before the HTTP server, every setting has a flag and a `CICADA_…` variable, and `cicada-cli` goes into `cicada-app`, with the terminal UI and each store as features that are off by default. |
| [0028](0028-the-ready-made-actors.md) | The ready-made actors: a `Failed` holds its cause, a turn creates an actor by its address, a supervisor restarts a child at fault once per incident by the order of its own mailbox and escalates by failing a message of its own (as a handler for too many restarts, refused for good for a child it cannot start), a stored message holds no address, and a topic delivers to each subscriber in a turn of its own. |
| [0029](0029-the-depth-of-a-value.md) | The depth of a value: a payload and a state hold at most 64 levels, refused like the other limits of a value (before the repeated id and the schema check over HTTP, at the call in a turn, as a failed turn for a new state, and at an operator's retry, `409`); values stored before are read as before; a `Failed` can be one level deeper. |
| [0030](0030-three-loops.md) | Three loops, each in a session of its own: design with the owner, build in a worktree, and review in any agent harness, handing over through files (`scripts/status.py`, `scripts/review.py`); changes are small, the builder runs targeted tests, reviews read rather than run the suite, and only blocking findings start one fix round. Partly superseded by 0055: one session, releases and the fast lane. |
| [0031](0031-durable-flows.md) | Host-named flow actors replay an ordered journal, commit one new step per turn, recover through an armed continuation and retain completed runs; external effects remain at least once, and the first journal contract includes durable sleep. |
| [0032](0032-timer-trace-links.md) | Observers select headers for delayed self-sends or other sends; cicada-otel starts timer traces with a link carried by prefixed propagation headers, preserving explicit parents and ordinary send propagation. |
| [0033](0033-listing-actors-with-state.md) | A typed actor-state listing and GET /actors/states reuse full actor snapshots, with one set-based read per page and ordinary address keyset paging. |
| [0034](0034-actor-change-hints.md) | Best-effort actor change hints with bounded resync recovery, shared-Store memory/SQLite coverage and transactional PostgreSQL notifications across upgraded nodes. |
| [0035](0035-actor-change-sse.md) | GET /changes exposes changed/resync hints as SSE, with fixed keep-alives, no replay, and the existing store and application shutdown lifetimes. |
| [0036](0036-register-contracts-without-hosting.md) | A core operation and PUT /types/{name} register contracts without handlers, recomputing hashes and preserving atomic first-registration-wins semantics. |
| [0037](0037-leasing-turns-outside-the-node.md) | Public core lease, renew and release operations use server policy, conservative handoff deadlines and epoch fencing for trusted external executors. |
| [0038](0038-completing-leased-turns.md) | Handler reports complete remote turns through one fenced commit attempt; shared server policy returns an explicit failure report after known rejection for safe caller retries. |
| [0039](0039-workers-over-a-turn-source.md) | Worker reuses the Rust executor over a public TurnSource, with per-turn deadlines, bounded shared capacity, explicit completion retries and independent shutdown. |
| [0040](0040-remote-turns-over-http.md) | Four JSON lease routes and ActorClient's TurnSource adapter preserve explicit completion results, fencing and uncertainty across HTTP peers. |
| [0041](0041-a-consumer-skill-with-each-release.md) | A consumer skill ships with each release and routes agents to the project's resolved Cicada source; guides own the knowledge and CI checks provenance and drift. |
| [0042](0042-app-workers-over-http.md) | App worker selects store or HTTP execution with explicit mode precedence, shared hosting, server-owned lease policy and independent Worker shutdown. |
| [0043](0043-deep-payloads-of-dead-letters.md) | Deep dead-letter payloads use an explicit JSON-text field with exact numeric parsing, ordinary redrive validation and a breaking backup/restore upgrade. |
| [0044](0044-flow-requests-waits-and-cancellation.md) | Flow sends, correlated reply waits and cancellation share one reserved wire shape, with phase journals and staged behavior: sends since 0.18.0, requests and single reply waits since 0.18.1, their deadlines since 0.18.2, joins of all or the first reply since 0.18.3, cancellation of a running run without cleanup since 0.18.4, and its cleanup, `Flow::on_cancel` over a journal of its own, since 0.18.5. |
| [0045](0045-docs-handoff-between-loops.md) | Builders hand off prose, integrate exact docs-owner fixes for blocking checks, and keep main green through normal review and release gates, since 0.18.6. |
| [0046](0046-local-checks-and-releases.md) | Local tree-bound check evidence gates main and version tags; pinned local publication replaces automatic Actions, and remote version tags stay immutable. Partly superseded by 0070: files under `openspec/` reuse a full pass. |
| [0047](0047-canonical-json-and-conformance-fixtures.md) | Fixed canonical/hash and remote-worker fixtures ship as a second verified release archive, with the current formatter and explicit tested dependency limits. |
| [0048](0048-node-details.md) | Optional hostname, Cicada version and label describe node rows; migration 7 is additive for running old nodes, and metadata does not establish identity. |
| [0049](0049-consumer-skills-as-a-plugin.md) | Consumer skills also ship as one Claude Code plugin following main, with workspace version checks and the portable release archive retained. |
| [0050](0050-actor-design-guide.md) | Actor design knowledge gets its own guide and a checked websocket session example with bounded replay and explicit client acknowledgements. |
| [0051](0051-interactive-actor-design-skill.md) | An interactive actor-design skill uses the sibling resolver, saves visual design progress and ships beside cicada in a backward-compatible versioned archive. |
| [0052](0052-actor-placement-by-claim-owner.md) | Immutable actor placement filters claims by node or worker identity, qualifies liveness and requires an upgrade of all claimers. |
| [0053](0053-a-bounded-pinned-process-example.md) | One pinned actor per process run, retained host handles/tombstones and explicit reconciliation after host restart. |
| [0054](0054-node-down-alerts-through-a-monitor-actor.md) | An optional singleton monitor publishes sampled node-down alerts through Topic with durable deduplication and explicit observation limits. |
| [0055](0055-one-change-loop-a-fast-lane-and-batched-releases.md) | One session runs the change loop with builder and reviewer subagents; a fast lane without a design for rustdoc, tests and internal refactors; landing pushes `main` and a batch of landed changes is released together, with E2E at the release. Partly superseded by 0073: two builders. |
| [0056](0056-shared-external-resource-crates.md) | A layer for an external resource that two or more consumers need may live in an optional crate of the workspace (`cicada-containers`); the core and the other crates never depend on it. Supersedes in part 0011. |
| [0057](0057-a-reconciled-container-actor.md) | A ready-made container actor in `cicada-containers`, under a host-chosen type name, reconciles one armed poll at a time toward a goal, finds its container by a name made from its key, reports its end before removal and leaves placement to the host (ADR 0052). |
| [0058](0058-a-ready-made-permit-pool.md) | A ready-made permit pool, `cicada.permits`, with its capacity in the state, one permit per `Acquire` keyed by a request ID, FIFO grants fenced by a number that only goes up, release only by an explicit `Release` with that number or when a grant notice fails before it was delivered, and notices outside an `Acquire` sent in a turn of their own. |
| [0059](0059-a-ready-made-job-graph.md) | A ready-made job graph, `cicada.job-graph`, one run per actor with the graph as its state, refused at the create for a cycle, an unknown need or out of bounds; jobs are messages to a target per job, sent in turns of their own up to an in-flight limit, with numbered attempts; only a result for the current attempt is taken; a failed job blocks its dependents, and the end is reported to a target. |
| [0060](0060-cancel-and-skipped-dependents-in-the-job-graph.md) | The job graph skips the dependents of a failed, skipped or cancelled job, ends `succeeded`, `failed` or `cancelled` from its jobs, watches each job's target to fail a job whose message failed or whose worker went away, and takes `Cancel` of one job or all, telling a dispatched worker through an optional cancel message type in a turn of its own. |
| [0061](0061-retry-in-the-job-graph.md) | `Retry` of a failed or cancelled job in the job graph puts it back to waiting for its next attempt, recomputes the skips and reopens an ended run; it is refused for a job that is not failed or cancelled or whose need is failed, skipped or cancelled; the end report carries the number of its end. |
| [0062](0062-a-failure-kind-on-the-container-end.md) | A `failed` container end carries a kind (`notStarted`, `outOfMemory`, `runtimeEnded`, `missing`, `runtimeErrors`); out of memory is the runtime reason `OUT_OF_MEMORY`; a replayed create step adopts a started container; each request can have its own timeout; the contract change makes the batch 0.21.0. |
| [0063](0063-a-watch-of-an-actor-that-must-exist.md) | `Turn::watch_existing` watches one actor that must exist: at the commit it sets the watch when the actor is there and otherwise puts a `Stopped` (cause `deleted`, `by` null) into the watcher's mailbox in the same transaction; the remote turn report carries `existing: true`. |
| [0064](0064-background-tasks-of-an-app.md) | `App::task` runs a host's task with the node: started after `on_start`, told to stop when the node's stop begins and sharing its grace period, the store closing last; an early end, error or panic stops the node and fails the command; an `App` with a task refuses an HTTP worker. |
| [0065](0065-container-progress-through-a-file.md) | With `progressType` on `Start`, the container actor sets `CICADA_PROGRESS_FILE`, reads the file at each running poll and before the end, and sends `ContainerProgress { key, seq, text }` when it changed; best effort; late progress is dropped by `seq`; a contract change (0.23.0). |
| [0066](0066-container-outputs-at-the-end.md) | With a store on the actor, the container actor holds an end the container ran for as pending in the phase `Collecting`, drains the rest of the log and copies the job's output folder into the store, then records and delivers the end with an `outputs` report; a refused file is skipped; errors in a row keep the recorded outcome; a contract change (0.23.0). |
| [0067](0067-a-placement-pool.md) | A ready-made placement pool `cicada.placement/<pool>`, created with its settings in its state: nodes renew `Offer`s of instance, labels and places; the pool's own timer marks a quiet node silent (no new places, one notice in its own turn) until it offers again; the line ships as one release. |
| [0068](0068-asks-in-the-placement-pool.md) | Asks in the placement pool follow the permit pool's protocol with `PlacementAnswer`; a grant goes to a live node with every need, most free places first; the line is served in order but skips asks that cannot be placed now; holders are capped per pool. |
| [0069](0069-a-second-machine-under-one-node-id.md) | An offer from another instance under a live node's id changes nothing, marks the node in conflict and sends one `conflict` alert; the mark ends at silence or after one quiet silence time; extends ADR 0067. |
| [0070](0070-openspec-files-reuse-a-full-pass.md) | Any non-executable regular file under `openspec/` may reuse a full pass of the gate, so an archive commit needs no second full run; review markers are written as plain files; partly supersedes ADR 0046. |
| [0071](0071-a-duplicate-node-reported-by-its-member.md) | A placement member that sees its node row written by another host skips its offer and reports `Duplicate`; the pool marks the node (ADR 0069's mark with a host), alerts once and places nothing there while marked; `NodeConfig::hostname` sets the name a node writes; the identity folder is locked; extends ADR 0069. |
| [0072](0072-one-live-holder-per-resource.md) | An offer may name a resource key (Docker's daemon id from `RuntimeInfo::id`); one live node holds a key, a second live node offering it is ignored, its contest kept in a pool-level list and alerted once; extends ADRs 0069 and 0071. |
| [0073](0073-two-builders-in-the-change-loop.md) | Two builders at once when their changes share no crate (a `Crates:` line), the second on Codex; every change reviewed by the other model; one gate run and one landing at a time; supersedes ADR 0055's one-builder rule. |
| [0074](0074-a-tray-crate-next-to-the-app.md) | A portable `cicada-tray` model starts an in-process HTTP worker from a host's `App` factory and tracks its state and turns. The macOS menu comes later. `App::type_names()` lists hosted types and `App::on_worker_ready` reports when the worker starts. |
| [0075](0075-a-full-pool-says-so-once.md) | A full placement pool accepts and ignores a new node's offer instead of refusing it, keeps one pool-level `full` mark and sends one `full` notice per full period; the mark ends one silence time after the last ignored offer or when a node is added; extends ADR 0067. |
| [0076](0076-a-native-macos-inspector.md) | A native macOS inspector crate; only the tray may depend on it. |

## Design questions


| Question | Decision |
| --- | --- |
| Crash loops | The claim limit in the core, on by default (ADR 0025): a message with 5 lost claims ends `failed`; `lostClaims` is on the envelope and in `/messages/{id}`. |
| Contract changes | Strict contract-hash equality; a node with a different contract for a registered type name fails to start. Contracts include the generated schemas, so a schemars upgrade can change hashes. Doc comments (`description`) do not count in the hash. |
| State evolution | No migrations; changes must be additive with defaults (`#[serde(default)]`). |
| Observer data | `headers` on the envelope, which an observer may add to a turn's sends; `correlation_id` is kept (the HTTP contract uses it). |
| Send to an absent instance inside a turn | The whole turn fails at commit: outcome `failed` with the reason, no effects. |
| Admin delete | Allowed: `DELETE /actors/{type}/{key}`. |
| One-way messaging | Core keeps one-way sends; flows add durable reply waits (ADR 0044). |
| Defaults | Lease 30 s, heartbeat 10 s, poll 500 ms, max turn 15 min, retention 7 days; all configurable. |
