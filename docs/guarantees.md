# Guarantees and their tests

Each guarantee of [the architecture](architecture.md) (G1–G6) and each of its store requirements (S1–S10), with the
tests that prove it. One line says what the guarantee holds; the architecture has the full text. A test is named
`path::function`, the path of its file from the root of the repository.

The store requirements are proved by the conformance suite (`crates/cicada/src/tests/conformance`), which runs every
case on each store: the in-memory store, SQLite and PostgreSQL. A row names the case, not the copy of each store. The
randomised node simulation (`guarantees_hold_under_faults`) checks G1, G3, G4, G5, G6 and S8 on the history of runs
under injected faults.

A test of `cicada-examples` (`examples/tests/docs.rs`) reads this table. It fails when one of G1–G6 and S1–S10, or
another guarantee the architecture names, has no row, when a row names no test, or when a named file holds no function
of that name. It does not run the tests; `cargo test` does. A change that adds a guarantee, or a test that proves one,
adds it here.
