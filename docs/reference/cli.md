# The command line

The help of the plain `cicada` binary and of each of its commands, as `--help` prints it, with the terminal UI (the
feature `tui` of `cicada-app`). A binary built from `App` with types has the same commands under its own name, and
`serve` and `worker` too; their help is at the end, for a binary called `myapp`. See [the app guide](../guide/app.md)
for what the commands do.

This file is generated by a test of `cicada-app` (`crates/cicada-app/src/cli_reference.rs`) and checked by it: do not
edit it. When the help changes, run the tests with `CICADA_UPDATE_CLI=true` and commit the file:
`CICADA_UPDATE_CLI=true cargo test --workspace`, or `CICADA_UPDATE_CLI=true cargo test -p cicada-app --features tui`.

## `cicada`

```text
Talk to a Cicada node over its HTTP API

Usage: cicada [OPTIONS] <COMMAND>

Commands:
  get          List or show resources
  describe     Show one resource in full
  create       Create an actor or a watch
  delete       Delete an actor, a type registration or a watch
  send         Send a message to an actor
  cancel       Cancel a message, messages, or a running turn
  retry        Send failed or cancelled messages again
  deliver-now  Make a pending message due now
  pause        Pause an actor's mailbox: messages queue up, no turn starts
  resume       Resume a paused actor
  purge        Give outcome `purged` to every pending message of an actor
  stats        Count actors and pending messages under a prefix
  health       Whether the node runs and its store answers
  config       Read and change the config file
  tui          Browse and act in a terminal UI
  help         Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

Global options:
      --context <CONTEXT>
          The context of the config file to use

      --server <SERVER>
          Base URL of the API; wins over CICADA_SERVER and the context

      --token <TOKEN>
          Bearer token; wins over CICADA_TOKEN and the context

  -o, --output <OUTPUT>
          Output format (`describe` defaults to yaml)

          Possible values:
          - table: Aligned columns
          - wide:  Aligned columns, more of them, and full instants
          - json:  The API's JSON view, pretty-printed
          - yaml:  The API's view as YAML
```

      --lease-ttl <DURATION>
          The lease of a turn [env: CICADA_LEASE_TTL] [default: 30s]
      --heartbeat-interval <DURATION>
          How often a lease is renewed [env: CICADA_HEARTBEAT_INTERVAL] [default: a third of the lease]
      --poll-interval <DURATION>
          The longest sleep of the dispatch loop [env: CICADA_POLL_INTERVAL] [default: 500ms]
      --shutdown-grace-period <DURATION>
          How long running turns may take to finish when the node stops [env: CICADA_SHUTDOWN_GRACE_PERIOD] [default: 30s]
      --max-turn <DURATION>
          The longest turn of a type that sets none [env: CICADA_MAX_TURN] [default: 15m]
      --max-lost-claims <N|off>
          The claim limit: a number, or off [env: CICADA_MAX_LOST_CLAIMS] [default: 5]

HTTP:
      --server <URL>    The base URL of a server's API, which selects HTTP mode [env: CICADA_SERVER]
      --context <NAME>  The context of the config file, which selects HTTP mode [env: CICADA_CONTEXT]
      --token <TOKEN>   The bearer token, in HTTP mode only [env: CICADA_TOKEN]

Mode: --store runs the turns on the store, --server or --context through a server's HTTP API; not both.
Without either, a non-blank CICADA_STORE selects the store, else a non-blank CICADA_SERVER or CICADA_CONTEXT
selects HTTP; a token, or the current context of the config file, alone selects nothing.

Over HTTP the server owns the store and the leases: --store-schema, --store-pool-size, --retention, --lease-ttl,
--heartbeat-interval and --max-lost-claims are refused, and their variables are not read. The server, the token
and the headers come as for the operator commands. A binary with App::on_start or App::task cannot run over HTTP.
