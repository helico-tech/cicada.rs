# 15. Multi-node end-to-end tests against PostgreSQL

## Goal

Multi-node end-to-end tests against PostgreSQL.

## Acceptance criteria

- Cluster tests of `e2e-tests` ported: API, examples, restart, node faults, ordering, outages.

## Plan

Port Kotlin's `e2e/` (compose stack, README) and `e2e-tests/` (the eight test classes and their Gradle wiring) to the
crate `cicada-e2e` (`e2e/`).

- `e2e/docker-compose.yml`: the Kotlin stack (PostgreSQL 18, `node-1`..`node-3` hosting all groups, a send-only node,
  short timings overridable from the shell), built from `sample-service/Dockerfile`; project `cicada-rs-e2e`, image
  `cicada-rs-sample:e2e`, host ports 9081–9084 and 25432 (9090/9091 for the SQLite nodes), so the Kotlin stack can run
  beside it. No `JAVA_OPTS`.
- Harness in `e2e/src/` (library): `docker` (CLI, compose project, `SingleNode` for `docker run`), `cluster` (`Node`
  with raw `reqwest` and typed `ActorClient` access, `eventually` polling with deadlines, `Cluster::restore`),
  `ordering` (`send_step` with same-id fail-over, `assert_mailbox_order`), and `run_suite`.
- Lifecycle (replaces the Gradle wiring, JUnit ordering and extension): one test binary `tests/suite/` with a single
  `#[test]`; one module per Kotlin class, run in the Kotlin `@Order`. `run_suite` returns at once unless
  `CICADA_E2E=1`; else it removes leftovers, builds the image once, `compose up --wait`, runs the classes (hooks as
  JUnit's `@BeforeAll`/`@AfterEach`/`@AfterAll`, each test and hook under a 4-minute bound with its panic caught as
  its failure), and always saves the compose logs to `target/e2e-logs/` and runs `down -v` (and removes the SQLite
  containers and volume): at the end, while unwinding from a panic (a drop guard), and on Ctrl-C. Failures are
  reported together after the teardown. `CICADA_E2E_ONLY` selects tests by `Class::test` substring (Gradle's
  `--tests`).
- Port `e2e/README.md` (run, drive by hand, clean up).

## Progress log

- 2026-10-07: compose file, README, harness and the eight classes written; `cargo test -p cicada-e2e` without
  `CICADA_E2E` passes at once, clippy is clean.
- 2026-10-07: first real run: 16 of 17 `Cluster*` tests passed; `ClusterRestartTest` failed: after
  `docker compose restart` a node started while the `postgres` host name did not resolve yet, sqlx fails at once on
  that (it only retries "connection refused" within the acquire timeout), and the node exited (`restart: "no"`).
  The Kotlin node escapes this only by its slower JVM start. Fix in `sample-service/src/app.rs`: the node retries an
  unavailable PostgreSQL store at start for up to 60 s (1 s apart, logged) before it gives up.
- 2026-10-07: three consecutive full runs passed (30 of 30 tests each): 179.9 s, 169.6 s, 172.4 s, including the
  image build (2-8 s with docker's and cargo's caches) and `compose up --wait` (14-16 s). The first image build of a
  clean machine compiles the workspace in Docker and takes several minutes more. Teardown checked: after a failing
  run (drop guard), after passing runs, and after SIGINT (exit 130, containers, network and volumes gone).
- Ported classes (Kotlin → `e2e/tests/suite/`): `ClusterApiTest` → `cluster_api.rs` (11 tests),
  `ClusterExamplesTest` → `cluster_examples.rs` (5), `OrderingTest` → `ordering.rs` (2, with `Ordering.kt` in
  `src/ordering.rs`), `NodeFaultTest` → `node_fault.rs` (4), `OutcomesUnderFaultTest` → `outcomes_under_fault.rs` (1),
  `StoreOutageTest` → `store_outage.rs` (1), `ClusterRestartTest` → `cluster_restart.rs` (1), `SqliteNodeTest` →
  `sqlite_node.rs` (5); `Docker.kt` and `Cluster.kt` → `src/docker.rs` and `src/cluster.rs`; the Gradle wiring →
  `run_suite` in `src/lib.rs`.
- Deviations from Kotlin, on purpose:
  - One `#[test]` runs the whole suite; failures are collected and reported together after the teardown (JUnit
    reports per method). Test names are the Kotlin sentences in snake case.
  - Kotlin's `Random(42)` delays in `OrderingTest` become a seeded xorshift: different, still deterministic, delays
    in the same 0.3–3 s range.
  - Container names `cicada-rs-e2e-sqlite` / `-auth`, volume `cicada-rs-e2e-sqlite-data`, logs in
    `target/e2e-logs/`.
  - The pause test keeps Kotlin's fixed 4 s wait after the unpause: it checks that *nothing* changes (the stale
    commit is fenced), which no condition can poll for.
