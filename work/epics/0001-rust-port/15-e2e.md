# 15. Multi-node end-to-end tests against PostgreSQL

## Goal

Multi-node end-to-end tests against PostgreSQL.

## Acceptance criteria

- Cluster tests of `e2e-tests` ported: API, examples, restart, node faults, ordering, outages.

## Plan

Port Kotlin's `e2e/` (compose stack, README) and `e2e-tests/` (the eight test classes and their Gradle wiring) to the
crate `cicada-e2e` (`e2e/`).

- `e2e/docker-compose.yml`: the Kotlin stack (PostgreSQL 18, `node-1`..`node-3` hosting all groups, a send-only node,
  short timings overridable from the shell), built from `sample-service/Dockerfile`; project `cicada-rs-e2e`, image
  `cicada-rs-sample:e2e`, host ports 9081–9084 and 25432 (9090/9091 for the SQLite nodes), so the Kotlin stack can run
  beside it. No `JAVA_OPTS`.
- Harness in `e2e/src/` (library): `docker` (CLI, compose project, `SingleNode` for `docker run`), `cluster` (`Node`
  with raw `reqwest` and typed `ActorClient` access, `eventually` polling with deadlines, `Cluster::restore`),
  `ordering` (`send_step` with same-id fail-over, `assert_mailbox_order`), and `run_suite`.
- Lifecycle (replaces the Gradle wiring, JUnit ordering and extension): one test binary `tests/suite/` with a single
  `#[test]`; one module per Kotlin class, run in the Kotlin `@Order`. `run_suite` returns at once unless
  `CICADA_E2E=1`; else it removes leftovers, builds the image once, `compose up --wait`, runs the classes (hooks as
  JUnit's `@BeforeAll`/`@AfterEach`/`@AfterAll`, each test and hook under a 4-minute bound with its panic caught as
  its failure), and always saves the compose logs to `target/e2e-logs/` and runs `down -v` (and removes the SQLite
  containers and volume): at the end, while unwinding from a panic (a drop guard), and on Ctrl-C. Failures are
  reported together after the teardown. `CICADA_E2E_ONLY` selects tests by `Class::test` substring (Gradle's
  `--tests`).
- Port `e2e/README.md` (run, drive by hand, clean up).
